VOIX · BRAND GUIDE · BOOK 02

The desktop app gets out of the way.

The marketing brand promises personality. The product brand delivers it by being a quiet, well-made tool. Native chrome. System fonts. The puck is the one place character lives.

N° 01 · PHILOSOPHY

Two brands. One product.

The marketing brand and the product brand share DNA — the puck, HA blue, the wordmark — but they speak different dialects. Treat them as a parent-child relationship.

The mental model: the marketing brand is the advert. The desktop brand is the device. An advert can shout. A device should not.

N° 02 · CHROME

Native, always. No exceptions.

Window chrome, sidebar materials, form controls, focus rings, scrollbars, context menus — all platform-native. Don't reinvent any of it.

macOS

Liquid Glass.

Translucent sidebar materials. SF Pro Text for all UI. Native traffic-light controls. Use NSVisualEffectView for sidebar and toolbar surfaces.

WINDOWS

Mica.

Mica material for window backgrounds, opaque for sidebar. Segoe UI Variable. Fluent design controls. WinUI 3 widgets where possible. System accent respected on selection, focus, links.

N° 03 · TWO BLUES

System accent and HA blue. Different jobs.

Two blues that look similar and do different things. The split is what keeps the app feeling native while still being Voix.

System accent#007AFF / #0A84FF
  • Sidebar selection highlights
  • Text input focus rings
  • Hyperlinks and secondary actions
  • Selected list items, dropdown values
  • Form button defaults
  • Anything that should respect the user's OS accent setting
HA blue#03A9F4
  • The puck's inner circle (default Conversation mode)
  • "● NOW HEARING" / "● LIVE" status pills
  • "VOIX" speaker prefix in transcripts
  • Active-mode tag on the modes list
  • Pulsing rings emanating from the puck
  • Brand-owned moments only — never chrome

In dark mode the system accent shifts to its brighter sibling. HA blue does not — it's a brand colour, not a system colour. That means HA blue must be tested against both light and dark backgrounds and rejected if it doesn't read on one.

DO

Let the user's system accent appear in the sidebar, focus rings, and links. The app should feel like it belongs on their machine.

DON'T

Override system accent with HA blue. The user picked purple for a reason — they want purple selection highlights. Voix is not bigger than that choice.

N° 04 · MODE PALETTE

Twelve colours for modes.

Modes get their own colour. The desktop brand's exception to "three colours full stop" — but constrained to a curated palette so users can't break the system.

WHY 12, WHY THESE

Twelve is enough to feel free, few enough to feel curated. Five (where this guide started) makes users hit the wall the first time they create a mode that isn't Conversation, Dictation, Code, or Thinking. Twelve covers genuine personal expression without devolving into a colour picker.

Six saturated, six soft. The saturated row is for work modes — bold colours for things you do often. The soft row is for gentler modes — bedtime check-ins, meditation prompts, anything that doesn't want to shout from the menu bar.

Evenly distributed across the hue wheel. Two blues (HA + sky), two oranges (amber + peach), one red-orange (coral), two greens, two purples, one pink, one yellow, one neutral. No colour is too close to another — every mode looks distinct in the sidebar.

No gradient. No saturation control. No hex input. Users pick from twelve. That's the whole UI. The discipline is the brand.

DO

Use the mode colour everywhere that mode appears: sidebar pip, mode card preview, status pill when active, the puck's inner circle during the session.

DON'T

Bring mode colours into chrome. The lavender for "Bedtime mode" never recolours a button or a focus ring — only the puck and direct mode-referencing UI.

WHY THIS WAY

The puck is the protagonist, but it's modest. 110px in a default window — large enough to be the focal point, small enough that you remember it's a small device on a shelf. Anything bigger and the metaphor falls apart.

Rings emanate only when audio is detected. Idle pucks are still. The animation is information, not decoration. Three rings at descending opacity so the most distant fades into the background — implies voice carrying through the room.

Transcript is mono timestamps, sans body. Timestamps are metadata in the system mono. Speech is body text in the system sans. The "VOIX" prefix is in HA blue — the one place the brand colour appears in the transcript, branding the response without colouring the words.

Sidebar shows sessions, not modes. The user opens the app to read what was said or keep talking — sessions are the most-touched thing. Modes are pinned at the bottom because they change less often.

WHY THIS WAY

Grid, not list. Modes are visual objects with colour identity — a vertical list would waste the most distinguishing feature (the coloured puck). Two columns gives each card breathing room, scales to four-by-three at wider widths.

Active mode is a tag, not a checkbox. The "ACTIVE" pill in HA blue is the single bit of brand colour intruding on the chrome — because this is a brand statement ("Voix is doing this now"), not a system state. Distinct treatment from sidebar selection on purpose.

Card border thickens when active. 2px HA blue border on the active card, plus a 1px shadow. A 1px border would compete with system selection-highlight. The 2px treatment matches the marketing brand's "featured card" pattern — a deliberate exception to the 0.5px rule.

WHY THIS WAY

Editable name and description as raw input fields. No "edit pencil" icon, no modal. Click the text, type. The styling matches the read-only view exactly. This is a Things / Notion pattern — the cheapest path to the most natural interaction.

Inline 12-swatch colour picker. One row, twelve circles, selected one ringed by its own colour. No HSL slider, no hex input, no "advanced" affordance. The constraint is the affordance.

System prompt is mono. The textarea uses JetBrains Mono — this is the one place users write code-like text into the app, and the mono treatment signals "this is configuration, not prose."

Auto-save, not save button. "Saved" badge top-right indicates state. Form changes commit on blur. No undo stack here — a product decision worth making explicitly later.

WHY THIS WAY

Three statuses, not five. LIVE (currently being used), IDLE (connected, ready), OFFLINE (not reachable). No "STANDBY," "CONNECTING," "READY" — the user doesn't need that granularity in a list view.

Status colours follow the brand split. LIVE is HA blue (a Voix-specific state). IDLE and OFFLINE are neutral system grays — because "off" isn't a brand moment, it's just a fact. Resist the temptation to make IDLE green or OFFLINE red; those add noise.

Devices and Settings share one screen. They're related setup tasks and the user enters them rarely. Splitting them into separate top-level views would inflate the sidebar for low-value navigation.

WHY THIS WAY

No puck visible. Settings is machine config, not a Voix moment. The brand sits in the titlebar wordmark; the body of the screen is pure system. Adding a puck would be ornament — the screen would be lying about its job.

Dark mode shown to prove the system holds. Every screen must work in both appearances. HA blue stays exact (#03A9F4 in both); system accent shifts from #007AFF light to #0A84FF dark. API keys are masked. Standard practice, but worth saying: sensitive values never display in cleartext. "Edit" or "Add" launches a secure input modal. The masked preview pattern (sk-ant-•••2f) is the standard.

N° 06 · NEVER

The desktop-specific traps.

Every desktop app brand fails the same way: it borrows web habits that don't survive on a window with real chrome.

NEVER

Use Instrument Serif in the app. The serif is the marketing voice. The app is system fonts only.

NEVER

Custom traffic light controls. No "designed" close/minimise buttons. The OS owns these.

NEVER

Override the system scrollbar, context menu, or text-selection colour. These belong to the user.

NEVER

Onboard with marketing copy. First-run is sober: connect a puck, confirm API key, go.

NEVER

Show the /vwa/ glyph in the app. Pronunciation is a marketing concern. People who installed it already know how to say it.

NEVER

Animate the rings on idle. Pulsing is reserved for actual audio input. Decoration animation is what bad voice UIs do.

NEVER

Ship a light-themed app on a dark macOS. The window must follow system appearance.

NEVER

Open the palette to a hex picker. Twelve colours, fixed. The discipline holds the system together.
